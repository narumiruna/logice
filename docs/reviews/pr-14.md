### R1 — Authentication timeout reaches telemetry handlers

- Source: https://github.com/narumiruna/logice/pull/14#discussion_r4363129184
- Thread: `PRRT_kwDOVNn7es6vu9Pg`.
- Severity: P2. This is a query response and timeout regression, not an authentication bypass.
- Relationship to goal: the PR adds session checks before existing query handlers. Those checks must not change the handlers' query deadline or error response contract.
- Supporting evidence: `Service.Wrap` replaces `r.Context()` with a five-second authentication context and passes that request to `next`. Both query handlers create a separate five-second query context, but return without a response if the request context is canceled. Thus the authentication deadline can end a query first and suppress the structured 503 response.
- Contradicting evidence: none. The parent request must still cancel a query when the client disconnects; preserving it does not remove that behavior.
- Outcome: already addressed by the fix in this branch. Authentication endpoints keep the bounded context. Session lookup uses that context and then cancels it. Query handlers receive the original request.
- Required change: keep authentication work bounded, release its context after lookup, and pass the original request downstream. Test slow authenticated trace, log, trace-detail, and Live queries. Also verify parent cancellation and authentication timeout behavior.
